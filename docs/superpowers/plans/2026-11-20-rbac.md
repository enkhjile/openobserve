# Modular Casbin RBAC Implementation Plan

> **For agentic workers:** Use subagent-driven-development to implement each task with independent review.

**Goal:** Implement the attached OSS RBAC specification with fail-closed server boundaries.

**Architecture:** An isolated Casbin engine consumes versioned organization policy documents. Existing metadata and authentication adapters provide durable state and stable principals. API and execution hooks enforce typed permissions.

**Tech Stack:** Rust, Casbin-RS, Axum, existing metadata Db abstraction, Vue.

**Spec:** ../../rbac/design.md and ../../rbac/requirements.md

## Global Constraints

Opt-in, authentication-independent, SQLite and PostgreSQL, no Enterprise implementation, no external authorization service, AGPL notices preserved. Branch feature/rbac. User request authorizes proceeding after architecture map.

## Review Focus

- Ingestion token usernames cannot impersonate user UUIDs.
- Missing asynchronous execution context denies.
- New routes do not gain implicit permissions.
- JOIN/CTE/UNION sources all receive checks before data access.
- Concurrent update and revocation cannot reuse stale grants.
